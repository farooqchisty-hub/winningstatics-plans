Winning Statics in ChatGPT

A free plugin in the ChatGPT directory. We do the thinking (store read, template library, QA). ChatGPT draws the ads with its own image model, on the user's plan. It's an acquisition channel: people who want the full pack buy on winningstatics.com.

Drafted 30 Sep 2026 · Status: plan, nothing built yet

The short version

  • What the user gets: paste a store URL in ChatGPT, get 3 ads built from our ranked template library, plus a gallery link on winningstatics.com.
  • What it costs us: one page fetch, one text call and a QA check per ad. Image rendering costs us nothing.
  • What it can't do: sell anything. OpenAI's plugin rules ban selling digital goods, credits, subscriptions and upgrade prompts inside ChatGPT.
  • First step: a 1 to 2 day test that answers the one open question: will ChatGPT render images when our plugin tells it to? If not, we stop there.
  • Total build: about 1.5 to 2 weeks before OpenAI's review, if the test passes.

How a session works

  1. UserTypes "make ads for mystore.com" or picks Winning Statics in ChatGPT.
  2. Our serverread_store fetches the page and runs our existing enrichment (brand, product, audience, 3 angles, hero photo). It returns a short brief the user can correct.
  3. Our serverplan_ads picks the top templates from 3 different styles in the ranked library, fills in the product details and returns 3 finished prompts plus the hero photo.
  4. ChatGPTRenders each prompt with its built-in image generation, following our skill's instructions. This part runs on the user's plan.
  5. Our serversave_ads receives the 3 images, runs our QA check (with the brand name, so it doesn't fail the buyer's own logo), stores them and returns a gallery link.
  6. UserOpens winningstatics.com/g/{id}: their 3 ads to download, with the normal site one click away.

Phase 0: the test (1 to 2 days)

A minimal server plus the skill, run against 5 demo brands from brands11.py. Each gate is pass or fail, and gate G1 decides whether we build anything else.

G1
Does ChatGPT draw the image? After plan_ads returns a prompt, does the skill get ChatGPT to use its built-in image generation? If not, we stop. OpenAI's docs don't say either way, which is why we test before building.
G2
Do the images come back to us? Does ChatGPT pass its generated images to save_ads as file inputs? If not, we drop QA and the gallery, the user downloads from the chat, and we lose tracking below the chat.
G3
Does it match the real product? Does ChatGPT use the hero photo our tool returns as a reference? If not, the skill asks the user to upload a product photo first.
G4
Is the quality good enough? We render the same templates in ChatGPT and in our pipeline, then score both with our QA prompt. ChatGPT passes if its QA pass rate is at least 80% of ours. Below that, a free sample would undersell the paid product.

The one thing you'd do: in ChatGPT, open Settings, then Security and login, turn on Developer mode, and add the server URL I send you. That takes about 2 minutes. I build and run everything else.

Phases 1 to 3

Phase 1 · MVP

3 to 4 days
  • Harden the 3 tools and the 2 internal routes, add R2 and the Supabase tables, run QA on saved images.
  • Gallery page with download and UTM-tagged links (utm_source=chatgpt).
  • Abuse limits: 5 sessions a day per IP hash, 3 ads per session, plus the rate-limit binding. Public URLs only.
  • Events through logEvent: session, plan, render, save, gallery view, site click.

Phase 2 · Directory submission

2 days + OpenAI review
  • Plugin package: plugin.json, skill, server link, and exactly 5 positive and 3 negative test cases.
  • Video walkthrough, release notes, and website, privacy, terms and support URLs (all HTTPS).
  • Listing copy with no pricing, promotions or comparisons, checked against the claims ceiling.
  • OpenAI hasn't published a review timeline, so the launch date depends on them.

Phase 3 · After launch

as needed
  • Inline carousel widget. Account linking so paid buyers can see their own pack in ChatGPT.
  • Move the gallery into the Replit site if it's converting.

OpenAI's rules and how we meet them

RuleHow we meet it
No selling digital goods, credits or subscriptions, directly or through freemium upsellsThe plugin is free and sells nothing. No tool output or widget mentions price, packs or buying.
No upgrade prompts, and no links to checkout or upgrade pagesThe gallery page has no checkout button. The site's normal navigation is there. This is the main review risk, so the gallery stays a plain results page.
Can't be worse than the same feature on your siteThe site doesn't offer "3 free ads from a URL" today. To be safe, put the same free 3 on the site so the plugin never looks like the lesser version.
Must do something ChatGPT can't do on its ownStore reading, a ranked library of 1,169 proven templates, per-style contracts and QA. We lead the listing with this.
Tool hints must match what each tool doesSet as in the tool contract table above.

Open risks

  • Prompts are visible. Users can see what our tools return in ChatGPT. The rotation, the 3-per-session cap and the IP limit stop anyone scraping the library in bulk, but some exposure comes with the model.
  • Terms and privacy pages. Submission needs live URLs for both. The terms page still has legal placeholders to fill before Phase 2.
  • Launch timing. The directory listing works as a public launch, so time Phase 2 with the site launch.
  • Plan limits. Free ChatGPT users have tighter image limits. The skill has to handle "you've hit your image limit" cleanly.

What we measure

Directory installs, then sessions, briefs confirmed, ads rendered, ads saved, gallery views, clicks to the site, and signups and purchases with utm_source=chatgpt. After 30 days live we review gallery-to-purchase conversion and decide whether to invest in Phase 3.
